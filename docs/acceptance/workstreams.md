## Reviewed implementation choices

The original plan proposed several candidate technologies. The final choices are recorded in [architecture decisions](../architecture/decisions.md): portable PostgreSQL geographic queries instead of a mandatory PostGIS dependency; publication-checked API media delivery with private S3 instead of unconditional public CDN caching; verified passwordless email plus configured OIDC/Apple adapters; and authenticated polling for group updates. Seller and door interfaces share the web/iOS client instead of requiring separate frontend projects.

Search uses venue name/description and explicit tag/location filters; occurrence pages expose authoritative ticket/table availability. Featured placements are curated, not a fabricated trending score. Offline scanning, web push, SMS, NPS collection and queue/current-occupancy measurement are not retained release features. The original 3D/map styling remains a reference; the new client implements real backend workflows without claiming pixel-identical presentation.

The OpenAPI document enumerates live routes, status codes, authorization, headers and core purchase schemas. Some less central command schemas remain generic objects whose owning service performs strict runtime validation; the first-party client uses shared types and regression fixtures. It is not represented as a fully generated third-party SDK. All v1 contracts remain additive; there is no previously released signed iOS build to certify yet.

## External completion evidence still required

Account setup enables verification that cannot be performed locally: Stripe onboarding and real sandbox payment/refund/dispute/payout journeys; sender-domain email and APNs/Wallet delivery; Linux container CI, cloud deployment/TLS/IAM, alert receipt, load and point-in-time restore; signed iPhone/TestFlight, Apple Pay/Universal Links and store privacy/review metadata. Sellers must approve actual commission/refund/dispute/tax/retention terms. These are tracked release obligations, not recorded successes.

Use [the release journey matrix](../release/launch-verification.md), then complete the artifact-specific approval manifest with actual reviewer/evidence references. Local test doubles prove domain and transport behavior; they cannot substitute for provider accounts, legal policy approval, a signed device or production operation.
