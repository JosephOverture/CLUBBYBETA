# M2 — identity and business access review

Local engineering gate, 2026-09-23. Built on the verified M1 baseline. Relevant code is under `identity`, `organizations`, `notifications` and `privacy`, with migration `002_identity_access.sql` and shared web/native access in the development consumer.

Implemented: real persisted users/guest principals; verified passwordless email with single-use expiring tokens and initiating-client verifier binding; optional signed OIDC token verification against configured issuer/audience/JWKS and nonce; explicit account linking; opaque hashed sessions; native refresh rotation/replay revocation; HttpOnly web cookies and CSRF/origin controls; secure native credential storage; logout, profile and recent-authentication checks. No client role selection or local persona can grant authority.

Business access: organization applications, pending/approved/rejected/suspended states, optimistic review versions, platform review queue, owner/manager/editor/door/finance capabilities, venue-scoped memberships, email-bound invitations and acceptance, invitation/member revocation, member list and append-only audit. Initial admin provisioning requires direct database access and an already verified account; no default admin credential exists. Native commerce stays disabled, and provider readiness stays false until the commerce workstream configures and verifies it.

Delivery/privacy: encrypted notification payloads, durable delivery jobs, idempotent local sink and Resend transport, bounded retries; external requests run outside database transactions. Account export is scoped to the caller. Deletion clears supported personal-data fields/exports, revokes sessions/memberships and suppresses known delivery records. Ownership/provider unlink obligations remain `review-required` and are never falsely marked completed. Later commerce/group schemas must extend export/deletion before their own phase passes. Real sender verification, provider revocation and retention approval are production gates.

Evidence: backend and consumer typechecks pass; API/worker builds pass; web and iOS bundles export; `pnpm test:database` passes 26 tests including M1. The 12 identity/access scenarios cover credential and nonce replay, invalid PKCE, expiry, cookie/CSRF behavior, cross-channel same-user identity, refresh-family revocation, suspended sessions, unauthorized roles, optimistic review conflicts, append-only audit, wrong-email/venue invitations, immediate membership revocation, provider email idempotency, scoped export/deletion and OIDC verification. `pnpm audit --prod --json` reports zero advisories.

Local startup smoke passed with persistent PostgreSQL, migration, seed, running API and worker. The launcher stores its database outside OneDrive, uses hidden processes, refuses occupied ports or a server it does not own, and preserves data on shutdown. No external email was sent, no live payment account was connected and no signed iOS device test is claimed.

Review conclusion: identity/access boundaries and the local adapters passed. M3 may build tenant-scoped catalogue and event workflows. Provider onboarding/capability synchronization joins the W11 integration in M4; domain-wide privacy completion continues as new data models land. This is a local engineering gate, not a production approval.
