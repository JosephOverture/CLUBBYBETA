# M3 — catalogue, events and media review

Local engineering gate, 2026-09-23. Migration `003_catalogue_events.sql` extends the verified identity/access foundation. Catalogue and events are shared by the web and iOS consumer.

Implemented: destination visibility and aliases; versioned, tenant-scoped venue editing and publication; audited ownership claims and commercial-mode changes; coordinate, text and tag search with filtered cursor pagination; private saves; explicitly curated discovery; weekly and exceptional opening schedules; full dated occurrences with immutable timezone/currency snapshots and explicit daylight-saving validation. Organizers submit versioned proposals; hosts request changes, approve or reject, with immutable review history and exactly one resulting event even under concurrent approval. Rescheduling/cancellation creates a durable change record. M4 must connect that record to the booking/refund system before any sale is enabled.

External events return a validated event-specific HTTPS checkout URL or the venue fallback. Their inventory, payments and tickets remain with the external seller. No local tickets or invented availability are produced for external listings. Public queries consistently filter venue/destination/event visibility; draft preview requires current tenant permissions.

Media uses bounded authenticated uploads, private local/S3 storage adapters, hash-bound retry, decoding/re-encoding, pixel and format limits, metadata removal, thumbnails and publication-aware serving. Host and organizer event artwork is scoped independently of the venue hero. Referenced media cannot be deleted. Abandoned uploads have durable cleanup. Account exports include saves, claims and authored media metadata.

Evidence: 39 tests across four files pass against disposable real PostgreSQL, including all previous gates.
