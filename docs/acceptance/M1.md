# M1 — platform foundation review

Local engineering gate verified 2026-09-23. This scope follows the user's instruction to prepare locally without external accounts.

Implemented: pinned pnpm workspace; Nest/Fastify API; PostgreSQL-only persistence; serialized, transactional, checksum-verified migrations; environment binding; readiness/liveness; typed public contracts, OpenAPI projection and shared web/iOS SDK; a minimal Expo development consumer; durable outbox, worker leases, fencing, receipts, retries and dead-letter states; validated configuration, bounded request size, CORS, security headers, safe error responses and redacted logging. Docker and CI definitions and local operating instructions are included.

Executed evidence:

- Original local scaffold baseline: seven package typechecks; 123 tests across 24 files. No original code/data was overwritten.
- New backend and shared packages typecheck; consumer typecheck; API/worker/migration production bundles compile.
- `pnpm test:database`: 14 tests passed against real disposable PostgreSQL 17.10. Includes concurrent migrations, drift rejection, environment isolation, atomic rollback, job deduplication, competing workers, stale-lease recovery/fencing, dead-letter handling, hidden catalogue records, invalid input, body-size limits and CORS/security headers.
- Web and iOS SDK adapters used actual HTTP requests to the same running Nest API and the same persistent venue. This is a channel-contract test in Node, not a Safari or iPhone test.
- Expo web export and iOS Hermes bundle export passed. App signing and device execution are not claimed.
- Production dependency audit: zero reported advisories after a narrow `xcode>uuid` override to 11.1.1. The xcode UUID call was exercised directly and the iOS export was repeated. See the [upstream advisory](https://github.com/uuidjs/uuid/security/advisories/GHSA-w5hq-g745-h8pq).
- Review fixed migration environment initialization to commit with the initial schema; checks database ownership before subsequent migrations. SQL files use LF through `.gitattributes` to preserve checksums across Windows/Linux.
- Root `index.html`, `milanmap.js`, `qrcode.js` remain unchanged. Original local Clubby project remains separate.

Limits carried to release gates: no cloud deployment or CI run, no Docker daemon/container execution on this machine, no signed iOS device check, no identity/commerce yet. Outbox handlers currently support bounded database effects; external delivery/payment handlers must implement provider idempotency outside database transactions in their own phases. M1 does not claim that business flows or a finished website/iOS UI exist.

Double-check conclusion: local foundation behavior and cross-channel contracts are verified. M2 may implement identity/access on this foundation. No live commerce is allowed by configuration.
