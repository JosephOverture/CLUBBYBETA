# Administration and market activation

The shared web/iOS client shows administration only to an active platform administrator. The API checks authorization independently. Users can be found by exact email or account ID. Suspension revokes sessions, push registrations and pending invitations; it preserves financial records and prevents admission of a suspended holder's ticket. Reactivation does not restore old sessions or invitations. The bootstrap command and grant/suspension operations serialize changes to protect the last active administrator. Grants and user state use expected versions and require recorded reasons.

Seller review includes application information, membership, commercial policy and venue visibility/model controls. An ownership transfer records the outgoing owner, incoming verified account, organization version and current policy. The incoming account must explicitly accept responsibility within seven days using a recent session. Changes to the organization or policy invalidate the request; revocation and acceptance serialize on the organization. Acceptance revokes the outgoing membership and outstanding staff invitations, grants unscoped ownership, and records an audit event. Administrators may revoke a pending request. Seller payment-account ownership must also be updated through the provider's authorized procedures; this workflow changes Clubby permissions only.

Migration 013 disables previously enabled market switches. A switch alone does not prove that a market has been reviewed. An administrator must record evidence for catalogue, provider support, refund/tax terms, payouts, local support and privacy; specify allowed seller countries; and set an expiry within one year. Reviews are immutable. A new review disables sales until explicitly activated. Activation also checks published catalogue, approved seller status, current provider readiness and accepted commercial terms. Checkout checks the review's expiry, country, currency, timezone and allowed seller countries again. Expired evidence prevents new purchases without cancelling existing entitlements. Tests use clearly identified fictional evidence inside isolated test databases; no production review is manufactured by seeding.

Service controls contain only a public banner, new-sales pause and an allowlist of feature switches. Group creation, transfer creation, wallet creation and chat sending can be paused independently. Existing bookings, admission credentials, transfer revocation, payment reconciliation and refund operations retain their domain authorization. Credentials and provider secrets cannot be stored in these public settings. Both clients read `/v1/bootstrap`; servers enforce each switch even if a stale client still displays a control.

The audit viewer supports actor, resource and exact action filters with numeric cursor pagination. Audit and market-review records reject mutation at the database level. Privileged user/grant/market-review/ownership commands require recent authentication. The administration screen reports server failures, retains entered review evidence, and reloads current versions after successful changes. A conflicting edit requires a refresh and a new review of the current state.

Validation is in `tests/administration.database.test.ts`, including revoked access, last-administrator protection, simultaneous grant edits, paid-account suspension, review expiry/mismatch, feature pauses, incoming-owner acceptance/revocation and audit pagination. Live provider approvals and jurisdiction-specific commercial/privacy review remain deployment inputs.
